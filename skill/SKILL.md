# 总入口

你是在替两个人里的一个干活。另一个人和他的 agent 可能同时在动这个仓库。这一页告诉你先做什么、听到口令做什么、哪些事不能做。

## 一、每次开始先做这三步

不管人有没有说“开工”，都先做：

1. 运行 `node kit/kit.mjs start --who <lead 或 mate> --agent <你的工具名>`。
   - 不知道自己替谁干活，先问人。`lead` 是队长，`mate` 是队友。
   - 工具名写你自己，比如 `cursor`、`kiro`、`workbuddy`、`codex`、`claude`。
2. 用三句话向人复述：现在什么情况、我打算做什么、会动哪些地方。等人点头。
3. 运行 `node kit/kit.mjs claim ...` 认领，再动手。

跑不了命令的工具，见 `skill/phases/chat-tools.md`。

## 二、口令表

人说左边的话，你运行右边的命令。命令前面都是 `node kit/kit.mjs`，后面都要带 `--who` 和 `--agent`。

- “开工”：`start`，然后复述、等点头、`claim --task "做什么" --paths "会动的目录"`
- “收工”：`done --did "做到哪" --half "哪些改了一半" --verify "怎么验证" --next "下一步" --pitfalls "有什么坑"`
- “定了：……”：`decide "原话" --topic 话题`。取代旧决定加 `--replaces 编号`，旧文档要作废加 `--void 文件`
- “反馈：……”：`feedback "原话"`
- “对表”：`status`
- “交接”：`done ... --handoff`，见 `skill/phases/handoff.md`
- 要去问网页版 GPT 或 Claude：`opening --question "要聊的问题"`，聊完说“收口”，把决定卡用 `ingest` 贴回来

细节见 `skill/phases/daily.md`。

## 三、不能做的事

1. 不许把“已定的事”改回去。觉得哪条不对，告诉人，由人说“定了”来改。
2. 不许动别人认领的地方。`claim` 报撞车就避开，或者等对方收工。
3. 不许强制推送，不许“整个文件用我的”，不许删别人的文件。
4. 同步撞了、十分钟解不开：把活推到一个停车分支，回到主线，在现状板标“等人拍板”。
5. 不许把钥匙（各种 key、token、兑换码）写进仓库。仓库是公开的，写进去额度会被别人用掉。
6. 没推上 GitHub 的活等于没做。每做完一小步就提交并推送，最长不超过半小时。
7. 文件名只用英文和数字。文件内容用中文。
8. 图片的宽和高都不能超过 2000 像素。

## 四、怎么跟人说话

- 用中文，讲大白话，不用术语。
- 有不好的地方直说。给选项时讲清每个的好处和代价。
- 人说的每条决定和每条试玩反馈都要记下来，用上面的口令，不要只留在聊天里。

## 五、东西放在哪

- `state/decisions/`：已定的事。一条一个文件，只增不改，新的取代旧的。
- `state/board/`：现状板。每人一个文件，随时覆盖。
- `state/log/`：收工小结。只追加，平时不用读。
- `state/feedback/`：试玩反馈。
- `state/people.json`：有哪些人。`state/schedule.json`：比赛时间。
- `kit/`：命令。`skill/`：这一页和各阶段的说明。

你每次必读的只有 `start` 打印出来的那些，不用翻整个仓库。

## 六、现在建到哪一步

这套东西还在建。已经能用的：开工、收工、定了、反馈、对表、交接、开场白和收口、登记比赛时间、体检（`doctor`）。

还没建的：上线、转正、退回、开赛、收件口（现在是直接推主线）、入库、比一比、提交、复盘、投递包。人说到这些口令时，告诉他还没建好。

完整方案见 [超级 skill 方案（讨论稿）](https://github.com/historycrew5423-art/3d-/blob/main/docs/09-超级skill方案-讨论稿.md)。
